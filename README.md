# 北海道行程 App（PWA 最小版本）

## 上線（GitHub Pages）
1. 倉庫 Settings → Pages → Source 選 Deploy from a branch，Branch 選 `main`、資料夾 `/ (root)`。
2. 等 1～3 分鐘，網址是 `https://JutorLiao-1991.github.io/hokkaido-trip/`。
3. 用 iPhone 的 Safari 開啟 → 分享 → **加入主畫面**。
4. 在有網路時打開一次 App，之後沒訊號也能看（行程已快取）。

## 現在就能試玩
出發前請點右上角 ⚙ →「模擬時間」，選預設時間點，就能看到旅途中的畫面、按 ＋15／＋30／現在出發。

## 模擬位置（測試定位用）
⚙ →「📍 模擬位置」：選行程裡的地點或車站、貼上「緯度, 經度」，或按「放到模擬時間的那一站」。開啟後真實定位暫停，狀態卡、地圖、附近店家、站內導引、帶我回飯店都照這個位置算；頂部會顯示「回到真實定位」。設定存在手機，重開 App 仍保留，出門前記得停止。

## 匯出目前資料
⚙ →「📤 匯出資料檔」：把手機裡的完整資料（行程、行前清單、站內導引、日文站名）存成 `.json`，不含家庭代碼。要改行程或行前清單時，拿這個檔案當底稿，才能沿用原本的編號與勾選。

## 在 App 裡換景點、改時間
點時間軸上任何一站展開，可以：✎ 改這一站（名稱、導航地名、停留分鐘、備註）、＋ 後面加一站、🗑 刪除、↩ 還原。
- 改完立刻重算：只重排那一段（夾在兩個固定班次中間）；空檔先被壓縮，其次是「可壓縮緩衝」；放不下會警告「會來不及，超出 N 分」。
- 刪掉一站會留下空檔，後面的時間不會被往前拉。
- 固定班次（火車、預約）鎖定，不能在 App 裡改。
- 「還原本日」一鍵回到原版。改動存在手機，並隨「備份與雙人同步」一起同步。
- 沒有串即時交通資料：新地點的移動時間要自己估（可另加一個「移動」的站）。
- 測試：`node tests/engine_edits.test.js`、`node tests/prep.test.mjs`。

## 即時重排與置頂狀態卡
- 按 ＋15／＋30／現在出發時，時間軸後面的行程會立刻依你的調整重排（標「依你的調整」「時間已重排」），不會存成自訂。
- 會錯過固定班次而有較晚的備用班次時，狀態卡會出現「改搭 X，重排後面行程」；按下後該班改成備用班次，後面整段往後排，若撞到下一個固定行程會警告。
- 固定班次展開後可手動「改搭」其他備用班次，或「改回原班次」。改搭會存成自訂並隨家庭代碼同步。
- 狀態卡永遠置頂；往下滑會縮小成一行，點它可暫時展開。時間軸會對齊「現在」，60 秒沒滑動自動對回去，也可按「回到現在」。

## 手套模式、動畫與音效
- 右上角 🧤 切換手套模式：字與按鈕放大、底部按鈕改 2×2、按鈕可點範圍比外觀大、點到空白處會吸附到附近最近的按鈕、刪除／還原要按兩次、隱藏編輯按鈕、左右滑換日門檻降低。
- 任何模式都可左右滑動換日；時間軸有紅色「現在」線，切到今天會自動捲過去。
- 倒數最後 10 分鐘：狀態卡脈動並提醒一次。清單整區完成會撒彩帶。
- 音效（預設關閉，⚙ 設定裡開）：即時合成，不用音檔；iPhone 靜音時不會響。
- 尊重 iPhone「減少動態效果」設定。測試：`node tests/ux.test.js`。

## 班次看板與站內導引
右上角 🚉 打開 LED 風格的發車看板（依時刻表、非即時；附 JR 北海道運行情報連結）。預定班次綠色高亮，備用班次標「予備」。
點任何一班（或時間軸上的「🚉 站內怎麼走」）會跳出導引：先用定位判斷你在哪一站，再選你所在的入口／區域（札幌站還可選月台號碼），列出含樓層的步驟。
- 車站平面資料在 `stations.json`；哪一班車對應哪個車站、日文站名，跟行程一起存在雲端。
- 已整理：新千歲空港（2026 版 Floor Guide）、札幌（觀光插畫圖，未標電梯）、地下鐵大通與円山公園（交通局構內圖）、小樽（看板翻拍照重繪為 otaru_map.svg）、旭川（平面圖截圖）。
- 現場以站內標示與站務員為準。測試：`node tests/station.test.js`。

## 家庭代碼上鎖
行程、行前清單與站內導引對應存在 Firestore 的 `trips/{家庭代碼}_trip`。沒有代碼的人打開網頁只會看到鎖定畫面。
- 第一次在手機輸入家庭代碼後會記住，並快取在手機，之後沒網路也能看。
- 雲端有較新的版本時，打開 App 會自動更新；在 ⚙ 匯入新行程 JSON 也會同步上傳。
- ⚙ →「從這支手機登出」可清除手機裡的行程與代碼。

## 行前準備
最左邊的「行前」分頁：還要預約、證件保險入境、通訊電子、行李（孩子／大人）、購買清單。每項可勾選，每區都能自己新增項目（購買清單就是自己打字加）。清單內容跟行程一起存在雲端；勾選與自己新增的項目存在手機裡並雙人同步。

**不要在裡面輸入護照號碼、保單號碼等個資。**

### 雙人同步（選用）
預設資料只在這支手機。想讓兩個人同步，需要自己的 Firebase（免費額度夠用）：
1. Firebase 主控台建立專案 → Build → Firestore Database → 建立資料庫（正式模式）。
2. Firestore → 規則，貼上後發布：
```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /trips/{code} {
      allow get, create, update: if code.size() >= 20;
      allow list, delete: if false;
    }
  }
}
```
3. 專案設定 → 一般 → 新增網頁應用程式，取得 `apiKey`；專案 ID 在同一頁。
4. 專案 ID 與 API 金鑰（非機密）寫在 `app.js`，手機上只需在開啟畫面輸入**家庭代碼**（當密碼用，不要外流）。

衝突時每個項目以最後一次操作為準。同步失敗不會影響使用，資料仍留在手機。

## 行程資料放在哪裡
行程、行前清單、班次與車站的對應、日文站名**不在這個公開倉庫裡**，只存在 Firebase（用家庭代碼上鎖）和已輸入代碼的手機。

## 之後更新行程
⚙ →「📥 更新行程」→「選擇行程資料檔」選 `.json` 檔（或把 JSON 貼進文字框按「匯入」）。匯入後自動上傳雲端，另一支手機重新開啟就會更新。
在 App 裡做的修改（換地點、加站、改搭）以每一站的編號記錄，只要新檔案沿用同一個編號，修改就會保留。
改程式時請把 `sw.js` 裡的 `VER` 加 1，手機才會拿到新版。

## 行程 JSON 欄位
- `k`：fixed（固定：班次、預約）／flex（可調整：景點、用餐）／move（移動）／wait（候車緩衝）
- `c`：可壓縮的分鐘數（候車這類緩衝）
- `st`：confirmed／tentative／candidate／pending／backup
- `alts`：備用班次，`earlier: true` 表示比主線早
- `out`：戶外（用來提醒日落）；`dusk`：本來就是看暮色
- `q`：Google 地圖導航地名；`mode`：walking／transit／driving

## 已知限制
- 只在 App 開著時才能定位與倒數；沒有靈動島／鎖屏即時活動。

- 座標只放了少數車站與景點的概略值，僅用來顯示直線距離。
